# 普通训练到建设决策

`TrainingTurn.Development`保存行动前的建设状态：当前计划及顺序、六设施、发展Pt、规划预算、deck、发券阈值、当前券数和事件队列。编译检查它与训练状态的回合、阶段、Pt及队列一致；合宿设施也必须一致。执行器使用规则资源中的设施参数。缺少该建设状态时保留未知，训练在后续事件窗口停止。

普通成功训练在回合5..60跨过一个本期阈值时，收益、Pt、羁绊和次数按原有顺序结算，然后揭示事件211067／故事400011107／角色0／时机6。回合保持不变，协议阶段进入5。设施和券数此时尚未改变；同次训练触发的等级升级留在`PendingTrainingLevelCommandId`。

选项0使用既有建设结算：按有序计划的累计master边成本，与已经达到的发券阈值比较，应用可完成的设施前缀；票数分量要求已知前态0或1，结算后为1。当前券数的输入类型允许非负值和未知，终盘实包中的2张券可以完整保留，不能把建设局部适用条件当作全局持有上限。

自主训练跨阈值时直接结算设施与券，再按更新后的设施状态生成下一训练面板。条件回放保留建设确认，分量回放在 `ConstructionRemainderUnknown`（1007）停止并返回已提交的设施与券。

MCP 导入也支持当前已经可见的107／108建设事件。三个识别身份为211067／107／时机6、211076／107／时机10、211068／108／时机1，角色均为0。训练生成路径只安排第一种身份；比赛／Tucker的时机10及合宿延后108沿用各自的待处理边界。

## 证据与验收

当前触发域对照217局、5,564个严格普通训练机会：1,440次立即建设、4,124次不触发，零反例。turn60单独覆盖39次机会，其中1次过线、38次未过线；没有据此放开turn60的Tucker／岛训练触发。训练和建设确认的 11 组对照共重新读取 51 条原始记录。

扩大建设研究中的1,472条普通训练过线链全部在同一响应显示107；13条延迟反例来自比赛或Tucker的Pt事件。既有窗口（历史输出 `artifacts/research/blockers/construction-checkpoints/expansion-20261108/construction-windows.json`）

本次重新从更严格的普通训练机会集检查正负样本：217局、5,525个适用窗口，1,439次立即建设、4,086次不触发，0反例。排除1,077个不在当前触发域的窗口及5个非就绪窗口。该分母与建设研究的全部过线链不同。研究结果（历史输出 `artifacts/implementation/training-construction-01/study-01/summary.json`）

10组完整输入重新读取原始请求响应并核对身份与payload哈希，覆盖六个阈值、恰好达到阈值、同时产生升级待办、未过线和失败。只有行动前状态、实际动作及成功／失败条件结果进入执行器；建设事件身份由规则生成。后续包用于对照设施和券结算。原包导出（历史输出 `artifacts/implementation/training-construction-01/export-01/verification.json`）

条件回放沿用已识别的动作与成功标志。后续包用于核对设施和券数。上述窗口来自参与机制推导的育成。
