# 人员分布、得意率、Hint 与随机事件证据

核查日期：2026-11-05。当前交付是可重复的机会统计和候选模型对照，**没有新增人员、Hint 或事件的随机生成规则**。来源中的实验频数、作者猜想和已核对的包字段分别记录；不把旧日服社区公式直接认证为 Pioneer 机制。

## 公式来源与适用边界

### 人员出现与得意率

[GameWith 的支援效果实测](https://gamewith.jp/uma-musume/article/show/274990)给出 1,024 次训练的卡片观测，假设缺席约 10%、零得意时各训练约 18%，并明确表示样本存在波动、仅供参考。本次页面没有给出该项实验的精确采集日期；不能把页面近期更新日期当成公式重新验证日期。

[VIP Wiki 的「要検証」页](https://wikiwiki.jp/vip_umamusu/%E8%A6%81%E6%A4%9C%E8%A8%BC)并列了不同假说，没有提供当前 Pioneer 的随机规则证明。其引用指向 [2021-04 的研究帖](https://twitter.com/Lenry18/status/1380560738629025792)及[おがテツ 2021-04-28 的公式页面](https://www.ogatetsu.shop/entry/2021/04/28/024112)。后者本次无法直接读取；公式以可读取的 Wiki 为出处，不能声称核查了原文数据。

设卡片面板得意率为 `S`，直接固有得意率为 `U`；以下均不加入尚未解析的临时效果和剧本效果：

| 候选 | 得意位置概率 | 缺席概率 | 本次定位 |
|---|---|---|---|
| 早期线性近似 | `0.18 × (1 + (S+U)/100)` | `0.10` | 旧近似，只作基准 |
| 加法权重 | `(100+S+U)/(550+S+U)` | `50/(550+S+U)` | VIP 并列假说 |
| 固有乘法权重 | `W/(450+W)`，`W=(100+S)×(1+U/100)` | `50/(450+W)` | VIP 并列假说 |
| 固定出现率后分位置 | `0.90 × W/(400+W)` | `0.10` | 本项目显式比较假说，未找到本轮日文来源对当前 Pioneer 的证明 |

固定的其他训练权重为 100。线性模型超过其 90% 出席质量时，不截断后假装它仍是合法分布，而是停止输出该项基准。普通卡和友人卡不能直接混用同一个参数集。

这里真正不同的是**出现率是否固定，以及出现率是否随得意率、卡类型和剧本状态改变**。六权重模型也能写成先以 `(400+W)/(450+W)` 判断出现，再按 `W/(400+W)` 选得意位置；最终面板不能证明游戏内部抽签的先后顺序。

[2021-12-07 的个人博客及 12-30 更正](https://mysen.muragon.com/entry/2296.html)把结论从线性近似更改成权重公式，但正文下方还保留“固定缺席 10%”的旧段落。这也是不能拼接不同文章片段当成完整随机算法的具体例子。

### Hint 的基础率与分母

上述 GameWith 实测把基础值写成约 6%，其分母说明是“训练次数”，分子是“人员出现且有 Hint”；这是联合事件口径，不是已经出现后的条件概率。本分析器同时输出：

- `HintPerBoard`：该卡在完整面板上带 Hint 的次数 / 该卡面板机会数。
- `HintGivenPresent`：该卡带 Hint 的次数 / 该卡至少出现在一个训练的次数。

`LegacySixPercentHintExpected = N × 0.06 × (1+面板Hint加成/100)` 只是对旧近似的显式数值化，不是验证过的基础率。直接固有 Hint 加成非零时不输出这一简化基准，避免偷偷决定叠加顺序。

[2021-06-04 的日文支援效果说明](https://rojiuragame.com/2021/06/04/%E3%80%90%E3%82%A6%E3%83%9E%E5%A8%98%E3%83%97%E3%83%AA%E3%83%86%E3%82%A3%E3%83%BC%E3%83%80%E3%83%BC%E3%83%93%E3%83%BC%E3%80%91%E8%87%AA%E5%88%86%E3%81%A7%E3%82%B5%E3%83%9D%E3%83%BC%E3%83%88%E3%82%AB/)引用[おがテツ 2021-05-01 的 Hint 研究](https://www.ogatetsu.shop/entry/2021/05/01/205310)，但原研究本次无法直接读取，因而没有从转述补出精确常数、固有叠加规则或舍入方式。

不能将无岛设施时期的基准平移到所有先锋状态。[日文无岛 Wiki](https://wikiwiki.jp/sppenpen/%E7%84%A1%E4%BA%BA%E5%B3%B6)记载设施可改变出现率、Hint 率以及特定岛训练的必发/全部执行 Hint；[官方介绍](https://umamusume.jp/contents/game/scenario/designyourisland/)确认设施与独立岛训练系统存在，但没有给出这些完整数值公式。本地 master 的相关设施效果行可以用于后续核验，尚未在本模块解释其概率叠加与生效时机。

### Tucker 与临时效果

[タッカーブライン支援卡说明](https://kamigame.jp/umamusume/page/375484138699930139.html)描述共同训练影响其他卡下一回合得意率，外出事件也能影响下一回合得意率；页面本次可读，原始实验日期没有给出。

本地 master 卡 `30257` 的固有为 `type_0=122, value_0=19, value_0_1=60`。本地响应的 `gain_partner_support_effect_array` 确实含 `effect_type=19`，可见增量包括 20、60、120。**效果增量不等于当前生效效果快照**；空数组也不证明当前没有临时效果。当前报告保留原始增量、设施、评价会、岛训练和登场上下文，不将这些增量直接加进候选权重。

### 机会定义

先要求 exchange 为 `Paired`、endpoint 一致、响应成员包含当前源和包 ID，并有明确 `RunKey` 及 `scenario_id=11`。结构筛选要求 `playing_state=1`、待处理事件显式空、五项普通训练或五项合宿训练齐全且启用、预览参数数组非 null、六个编成位置和各自登场标志明确、人员和 Hint 数组类型正确。Hint 位置必须属于对应训练人员。岛训练 3101 是另一决策，不拿它与普通五训练重复计入分布。

此筛选定义参与分析的观测集合；实际抽样时点另行研究。样本选择只使用行动前信息。

相同 `(RunKey,turn)` 的重复面板只产生一个机会；不同回合即使结果完全相同仍各计一次。同回合多个不同面板会全部保留，单列计数并退出当前基准汇总，**不假定被排除项随机缺失**。同板不同上下文也保留在逐机会输出中，不能以“人员没变”丢弃效果变动。

| 项目 | 数量 |
|---|---:|
| 标准化观测 | 29,878 |
| exchange 不满足上述完整性条件 | 58 |
| 缺少明确 RunKey 的观测 | 4,076 |
| 完整 ready 帧 | 5,146 |
| ready `(run,turn)` 机会 | 5,139，来自 79 局 |
| 普通 / 合宿机会 | 4,297 / 842 |
| 重复 ready 面板帧 | 7 |
| 同回合不同面板 | 0 |
| 同面板上下文变化 | 5 组 |
| 尚未登场的卡—机会 | 158，独立分层，不当普通随机缺席 |
| 已观测 run-turn 没有 ready 面板 | 992 |
| 输入解析问题 | 0 |

992 项不是“漏了 992 次独立抽签”：其中可能包括不能训练的状态、赛事、初始占位、缺包和其他阶段。审计没有替这些状态构造抽签机会。

### 描述性结果示例

卡 `20079`、45 级、已登场、普通训练：3,906 个机会，来自 72 局。

| 观测 | 次数 / 分母 | 频数比例 | 名义二项 Wilson 95% 区间 |
|---|---:|---:|---:|
| 缺席 | 337 / 3,906 | 8.63% | 7.79%–9.55% |
| 得意训练 | 1,140 / 3,906 | 29.19% | 27.78%–30.63% |
| 面板带 Hint | 498 / 3,906 | 12.75% | 11.74%–13.83% |
| 已出现条件下带 Hint | 498 / 3,569 | 13.95% | 12.86%–15.13% |

该卡面板得意 50、直接固有得意 0。未调整权重模型预期得意 976.5 次；固定 90% 出现后权重模型预期 958.75 次；旧线性模型预期 1,054.62 次。实测 1,140 次比这些未调整值都高，**不能据此挑“最接近”的模型认证**。

所有 79 局均编成了固有 122 的卡；还混合了设施、临时效果及其他条件固有。当前缺少这些状态的完整时间线解析，也没有无 Tucker 的对照覆盖。出现率与 Hint 的模型残差因此同时包含遗漏条件，不只是抽样误差。

报告提供按局聚类的比例标准误：以每局成功数 `y_g` 和试验数 `n_g` 计算 `sqrt(G/(G-1) × sum((y_g-p*n_g)^2))/N`；一局时不估计。它允许同局内相关，但仍假设局间可视为独立，不能消除玩家策略、育成中止、捕获缺失及未解释上下文造成的选择偏差。名义 Wilson 区间也不能被当作已经满足独立性条件的机制置信区间。

## 随机事件与剧本长度

[官方 FAQ](https://support.umamusume.jp/faq/)只确认会话事件在特定时机可能发生、并非必发；编成支援卡会显著提高该卡事件出现机会。没有给出每回合基础率或按剧本长度缩放的公式。

[たんすい的 L'Arc 500 局研究，2023-11-01](https://note.com/tansui_carbs/n/n2f2c0944b7dd)专门研究回合开始的随机降心情事件，排除了训练失败、连赛、强制事件等；分母还排除海外远征等强制事件回合。作者报告 L'Arc 每有效回合 5.02%、每局 1.81 次，Grand Masters 对照为 4.35%、每局 1.91 次。这说明“每回合概率”和“每局总次数”可反向变化；不能把该降心情统计当作所有支援连锁事件的概率，也不能据它推出通用 `常数/剧本长度`。

另找到 [Alefrain 2023-09-07 原帖链接](https://twitter.com/Alefrain_ht/status/1699798041744793808)及其[日文论坛转载](https://uma-log.net/1525482/)。原帖本次读取被拒绝，转载主要讨论完走率；没有把论坛观点或图片中未核查的分母写成机制。

本地筛选后的事件字段有 15,853 次 pending 引用，按 `(run,turn,event_id,story_id,play_timing)` 得到 15,850 个可见身份，3 次重复引用。这个身份既不是独立抽签，也不是执行次数；同一事件同回合再出现可能是重复可见或另一轮处理。当前没有覆盖完整可触发池、未触发机会、排他顺序和历史触发条件，因此**不估计事件基础率，也不实现按剧本长度归一化**。
