# 三模式训练收益候选

`TrainingFormulaCandidate` 从当前属性、上限、成长、干劲、支援面板/羁绊、当前人员分配、设施状态与已生效的黄金船效果生成普通、合宿、岛训练的两层收益。生成器不读取观测预览作为输入；`TrainingModesAudit` 另行读取预览作对照。候选版本为 `jp-training-refit14-d6x3-r5-candidate-v5`；扩展设施输入范围及验证限制见[训练公式说明](training-formula-evidence.md)。下列实包计数保持原核验快照口径。

## 数值规则与输入边界

六个分量分别构造裸基础加成 `B`、角色成长 `G`、各项友情乘积 `F`、训练效果 `T`、人数 `N`、海之家效果 `H`、干劲效果 `M`。共用的整数化候选为：

```text
a = D6(B × G × F × T)
b = D6(a × N)
c = D6(b × H)
L = min(100, floor(R5(c × M)))
E = floor(L × 追加百分比 / 100)
```

`D6` 向下截断至六位有效数字，`R5` 四舍五入至五位有效数字，恰好半位向上。实现用 `BigInteger` 有理数及整数比较确定十进制数量级，不使用浮点、epsilon 或包 ID 分支。`RawGains` 的分子/分母保存未量化乘积；`TruncatedBeforeLimit` 保存经 D6/R5 后、100 截断前的整数。

普通训练的追加层没有额外 100 截断；合宿和岛训的 `E` 另外限制到 100。每层分别按 1200 分段转换：到 1200 的部分 1:1，剩余正部分除二向下取整且至少保留 1，最后按明确的属性上限截断。先结算下层，再以更新后的属性转换上层。技能 Pt 不折半。

| 模式 | 输入构造 |
|---|---|
| 普通 | 25 行普通基础表；本项训练等级；参加支援与明确属于先锋队的 NPC；最近已结算评估会加成 |
| 合宿 | `single_mode_11_shima_effect` 的成功基础行及必要设施条件；合宿 home 命令等级 5；本项参加人员；对应设施追加效果与海之家友情效果 |
| 岛训 | 同 master 的 3101 基础行；五项普通训练等级；六设施状态；明确的设施人员分配；各设施的基础、追加、友情设施数效果 |

固有 111 在合宿使用合宿命令等级 5，在岛训使用五项普通等级最大值。岛训训练/干劲效果先按“原子效果 × 设施到属性比例”逐项截断，再相加；主效果与固有效果不能预先合并。友情主效果与固有分别乘。基础属性/Pt bonus 不做该比例转换。

岛训人数项为 `1 + 0.05×屋外支援 + 0.01×屋内支援 + 0.02×屋外先锋队员`，屋内队员不增加此项。人数依赖明确的 deck/先锋队身份；不按 ID 大小猜身份。现有模块消费已给出的人员分配，不生成随机分配。

`TrainingEnvironment.GoldShipBoost` 表示已解析的本回合效果，null 表示调用方明确给出的无效果；未知应由输入构造层拒绝。黄金船事件 501007525 的显式指定命令在普通训练给该命令全部有效收益分量 `T+0.20`；岛训仅给对应主属性 `T+0.20`，不增加副属性或 Pt。合宿中的此效果尚未核验，明确拒绝。

原包适配通过本地 `card_data.chara_id` 识别黄金船，只有育成卡 100701 有本次事件证据。其它黄金船衣装明确拒绝，不能因为 card ID 不同就按“没有此效果”处理。

未知支援固有、团卡/未知支援类型、未知设施效果会失败。海之家非 Lv1、五项技能路线 Lv5 状态、合宿对应设施未建设也明确拒绝，因为当前完整预览未覆盖这些范围。其余已接受输入的覆盖仍有限，报告逐项列卡级和设施状态，不代表所有组合已验收。

## 可复跑核验

```json
{
  "name": "evidence_training_modes",
  "arguments": {
    "evidenceDirectory": "artifacts/research/blockers/island-training/expansion-20261108/audit",
    "masterPath": "<master.mdb>",
    "outputDirectory": "artifacts/evidence/training-modes-audit-new"
  }
}
```

输出目录必须为空。核验对 observations 按行处理，固定观测、动作、交换关联和 master 的 SHA-256，结束时再次比对。输出 `training-modes-audit.json`、`training-modes-samples.jsonl`、`training-modes-counterexamples.jsonl`。反例保留具体类型化输入、预测和观测；不通过改变常数隐藏差异。

筛样按单个训练命令的 `is_enable` 与明确禁用列表，某项禁用不会导致其它项被丢弃。`disable_command_id_array` 缺失、null 或类型不符会作为可用性未知排除；扩展研究提取中 69,453 个含 home 帧均明确提供数组，没有把缺失解释为空数组的依据。交换记录、观测和所用事件请求的端点必须一致。岛训原始参加位置跨全部设施检查唯一性，不能把重复 NPC 换算成两个人。

只比较实际存在的层：缺下层时仍核验可见上层，缺失不会补成预测值或零。`DecisionView` 另要求角色状态允许、待事件为空；仅显示启用或数值匹配不认证整个帧是行动决策点。用户确认有效的 `check_event` 与决策视图另计入 `PrimaryScope`。

黄金船事件核验要求同来源/育成/回合、前帧队首为 501007525、明确的非空指定命令信号、相邻请求响应配对，并核对实际请求的 event ID、current_turn、choice_number=0。仅有待事件不会直接生效。`load`、缺角色、孤包或不相邻观测切断该状态继承；中途未知状态不会当无加成继续生成。

上述“已知”只在当前相邻捕获窗口条件下成立。即使包 ID 连续，也不能证明游戏全部交换都已捕获；完整交换同时丢失是采集材料的能力边界，报告单独说明。没有跨来源拼接事件状态。

## 证据性质

公式来源是本地 `artifacts/research/blockers/training-settlement/refit-14/REPORT.md` 及其提取、事件与量化搜索产物。该研究的 279,770 条两库记录、4,271 条其它旧记录，以及 `island-training/expansion-20261108/REPORT.md` 的 53,179 条合宿/岛训记录存在语料重合，且参与候选选择，不能相加当独立样本，也不能称独立留出验收。多个操作次序仍满足已有观测，当前选定的统一步骤不是已识别的唯一服务端算法。

测试夹具 `tests/UmaAiSharp.Tests/Fixtures/training-modes-snapshots.json` 保存 11 个真实标准化快照及必要 master 行，含 17 张支援卡、三模式整数边界、黄金船、仅部分命令可用、上层单独可见的情况。它同样不是留出集。另有小型不变量测试核对原子效果截断、追加层上限、1200 分段及未知域拒绝。

最终统一构建通过，全项目 203 项测试通过、0 项跳过，其中包括这些训练夹具及端点错配、缺禁用列表、跨设施重复NPC、未核验黄金船衣装的输入拒绝。最终训练实现的 audit-02 与 audit-01 的计数、输入指纹、覆盖和逐项样本一致。

两类已识别耐力失败的条件化数值分量见[训练失败证据](training-failure-evidence.md)，岛训即时结算见[岛训练行动证据](island-action-evidence.md)。训练失败的随机结果/事件生成及其余后果、黄金船事件发生及目标抽取、人员分配生成、Hint 随机选择与完整事件调度、临时效果持续期、动态上限生成、原始溢出仍未完成。显示失败率与已识别失败结果的分量均不能验证实际失败概率；预览全匹配也不代表完整育成模拟已完成。
