# 比赛路线与评分核查

2026-11-05 的审计核对育成包中的已选目标 ID 与 master 的映射。模拟器的角色分支与这项审计分别说明如下。

## master 与状态边界

`single_mode_route` 将角色映射到 `race_set_id`，同时保留剧本、条件集合和优先级。`single_mode_route_race` 包含目标回合、顺序、条件、普通/决赛标识及条件分支字段。`single_mode_scenario_group` 决定哪些目标行适用于 Pioneer。`card_data` 提供育成卡到角色的映射。

当前育成的 `route_id` 和 `route_race_id_array` 必须保留在状态中。不能仅取同一 `race_set_id` 的全部 master 行生成赛程，因为这些行同时包含互斥候选和后来追加的目标。

示例：路线 122 的目标 1523 和 1524 同为第 5 项、回合 44，但目标赛、名次要求和条件标记不同。实包观察到 1523 被 1524 替换，随后还可追加目标 1529。目标 1530–1532 则使用决赛组编号 10001–10003，不能当作普通比赛 program ID。

`RaceRouteCatalog.ResolveSelected` 只执行明确 ID 的解析，检查育成卡、路线归属、剧本组及编号唯一性，保留原有顺序与全部条件字段。它既不猜选哪个候选，也不把结构对应当成目标完成条件已经解释。

角色分支由 `UmaAiSharp.Base.Races` 处理。成田白仁按经典年胜绩与事件选择进入强敌路线，爱丽速子按皋月赏参赛时的干劲决定下一目标，待兼福来在出道战和宝塚纪念后各抽一次。待兼诗歌剧和黄金旅程的固定赛程变化也按角色识别。Base 将已选目标与预约编入赛历，按分支替换、追加或移除目标，并给出角色分支奖励。Pioneer 读取当前局面，执行赛事和 URA。待兼福来两次抽签沿用 1∶1∶7 和 1∶1∶4 的拟合权重，玩家资料可交叉验证第 2、7 项目标随机决定。 [玩家赛程规划器作者说明](https://trap.jp/post/1367/) · [共通机制核查](base-mechanics.md#hint继承与路线)

### 分支奖励的结算时点

爱丽速子的 7 个「Report『透明な視線』」（501032402）配对窗口都在第 32 回合确认时给智力 +5。皋月赏参赛干劲好调以上的 6 局保留目标 184，普通的 1 局改为 296。后者在第 31 回合赛后、第 32 回合刚揭示故事时，目标均为 184、智力 422；确认后目标为 296、智力 427。普通路线的一例则是 184、智力 384→389。两例在 `capture-05` 的响应 49670→49672 和 `capture-03` 的 3748→3750。自主模拟在抵达第 32 回合时结算，条件回放在确认故事时结算。 [玩家整理的两条路线奖励](https://kamigame.jp/umamusume/page/208733114791426178.html) · [事件时点和换赛条件](https://gamewith.jp/uma-musume/article/show/343842)

从七局速子的赛前面板导入后，分 25 个前缀回放至各个确认点。`501032402` 使用 `changes: null`，第 31 回合赛后智力、第 32 回合确认前后智力均与实包一致。此前另一个皋月赏赛后故事 `501032421` 在 7 局都给技能组 20116、稀有度 1 的 Hint Lv1，当前普通目标赛奖励模型漏计该 Hint。另从这 25 个前缀的实际模拟状态读取后续赛历，第 33／34 回合的目标 ID 在全部 25 个确认点均匹配实包。

待兼诗歌剧的 7 个第 70 回合故事（501062406）窗口均给根性 +5。成田白仁第 49 回合的「岐」（501016409）有 5 个窗口，均选强敌路线，当帧资源差分均为零。四场强敌目标胜利另有 17 个窗口，覆盖 5 局、比赛加成 +28% 和 +30%。强敌赛获胜时按五维基础各 +5、技能 Pt +50 乘比赛加成，并发放对应 Hint Lv2。

## 2026-11-05 审计的覆盖边界

- 开局路线候选的条件与优先级选择，以及仅从已选 ID 推断替换或追加的触发时机。
- 目标条件类型 1、2、3 的完整解释及全部边界。
- 可选比赛的开放条件、粉丝要求、固定禁赛回合与特殊角色限制。
- 已确认育成层比赛结果分布、失败与重试、奖励、比赛后事件。

`single_mode_chara_program`、`single_mode_program`、`single_mode_turn`、`race_instance`、`race`、`race_course_set`、`single_mode_race_group` 及 `single_mode_race_restrict_turn` 提供后续核查所需的数据关系；表的存在不等于上述算法已完成。没有构造“全部目标都获胜”的路线执行器。
