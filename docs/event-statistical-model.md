# 事件基础资源模型

`pioneer event-model`从已配对的事件窗口和奖励声明中提取基础资源样本，按事件所属支援的卡面／固有加成进行分解。`pioneer model --events`将这些资源样本绑定到经验转移；未来执行按当前卡片和羁绊重算已校准资源，未解析后果单独保留为经验分量。

```powershell
dotnet src/UmaAiSharp.Cli/bin/Release/net10.0/UmaAiSharp.Cli.dll pioneer event-model `
  --events <event-transitions.jsonl> --model <源model.json> --output <新报告.json>
```

`--events`是已有事件研究的请求／响应窗口文件；`--model`用于关联已接受育成的来源、支援身份和等级。两项均只读。输出记录两项输入的哈希、master身份、样本、排除原因及未匹配窗口。

## 分解和抽样

`EventEffectScaling`处理目标支援自身的事件回复25及事件效果26，包含直接固有和已满足羁绊条件101的对应原子。回复作用于体力，事件效果作用于五属性和技能Pt；干劲、负奖励和体力上限不套用这两种倍率。[GameWith效果说明](https://gamewith.jp/uma-musume/article/show/274990)、[神ゲー公式](https://kamigame.jp/umamusume/page/147018895071419650.html)。

采用整数候选式`floor(基础值×(100+加成)/100)`。攻略将回复量的截断描述为推测；此处不把该舍入方式宣称为全部卡片均已独立实证的游戏真值。基础值必须能够唯一复算出奖励声明，不能以近似除法或四舍五入修补不匹配。

奖励声明保留封顶前的奖励。先用现有精确事件资源核比对当前选择的结果，只有资源投影唯一匹配的声明参与统计；封顶导致多个不同声明都匹配时排除。未解析奖励原子放入`RemainingEffects`，不会据此宣布完整事件完成。

查询先选择同一故事、同一条件的样本；没有样本时，使用用户授权的同类模型。条件包括所属类型、普通支援得意训练、事件编号、触发时机、年份、master显示进度及选项。输出`usesFamilyEstimate`区分两条路径，并记录样本数和育成数。两条路径都排除调用方指定的整局。

同类模型是统计推断。显示进度不是完整隐藏历史，接受样本还受玩家选项和资源投影可辨识性影响；得到的频数不能宣称为无偏游戏概率。无可用同类样本时明确失败，不创建零奖励或均匀分支。

`CompiledStatisticalEventRewards`在加载边界完成目标卡片倍率和结果数组编译。抽样只读取共享不可变数据并消费调用方独占的规则RNG；只有一个结果时不消费随机数。返回值同时包含资源分量和其余原子，调用方必须继续解释后者。

## 当前接入边界

`PioneerMasterCompiler.Support`可以直接由master卡号、经验、卡位和当前羁绊编译支援，不要求该配置存在真实育成样本。未知固有／支援类型仍保留明确错误。训练收益接口复用这一入口。

推荐的未来执行选择条件转移后，使用其已识别基础奖励替换资源净增量；卡位对应当前六卡，倍率按当前羁绊预编译，1200跨越、封顶、体力和干劲走已有精确资源核。4,900条绑定中3,187条仍有其他奖励原子，这些原子没有被宣称为规则已解释；经验路径保留来源转移中的其他后果。

当前已揭示的单结果选项使用当前奖励声明，并接入后续轨迹和根候选评价；没有历史选择记录的选项也能比较其已知奖励，后续调度明确采用该事件的选项集合。多结果声明缺少条件概率时停止，不等权补全。

跨配置路径保留来源事件卡位，再应用目标卡的资源倍率。来源故事、人员出现、连续进度和其余后果仍属经验迁移，并不证明目标卡也会发生同一专属事件。独立的`Estimate`同类频数接口与推荐的条件转移选择是不同估计器，不能把前者的样本分母当作后者的随机概率证明。整链验证和其他行动见[条件经验预测](conditional-forecast.md)。

局部资源复算及同类抽样测试不构成独立整局或建议质量验证。原始材料已经参与研究，不重新标为留出集。
