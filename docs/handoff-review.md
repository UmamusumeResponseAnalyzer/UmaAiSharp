# 移交包吸收与规则边界

材料为 `F:\Downloads\无人岛AI移交包_v2_2026-11-02\handoff`，其中的 C++ UmaAI、Kotlin umasim 和 Python 模拟器作为机制解释来源。以下记录片段执行阶段的吸收结果。回合推荐采用已有研究中最接近观测的解释；当前模型选择与参数见 [回合推荐实现](recommendation.md)。

## 源材料核查

`evidence_handoff` 只读核查七局派生 JSONL，保留源行号、回合标签和顺序。540 个动作帧含 60 个重复回合标签、468 个同回合转移、71 个推进转移及 1 个缺失前态。不能按“每回合一个命令”重新编号。完整前后态的资源 delta 均自洽，这只检验派生数据内部一致性。

`BetweenFrameResourceChanges` 单独记录上一帧后态到下一帧前态的资源差，不归因到上一动作。比较范围在 `ComparedResourceFields` 列出：五属性、体力、技能 Pt、发展 Pt、粉丝数；设施、羁绊、券和队列不属于这个差分。缺失快照和未知数值不补零。

源包没有原始 MessagePack 请求响应。其导出器还可能把缺失岛训练券转成零；因此这些派生数据不能独立证明完整轨迹或未知与零的区别。报告保存输入文件指纹并复核读取前后内容一致。结果位于 `artifacts/evidence/handoff-audit-02/`。

## 吸收的局部规则

### 普通训练的发展 Pt

Kotlin 候选经本地日服实包逐项核对后，实现于 `PioneerPointGain.OrdinaryTraining`：

```text
floor((60 + 6 × 参与人数) × (100 + 当前评审发展Pt加成 + 友情加成) / 100)
友情加成：具备友情资格时20，否则0
```

人数包括参加训练的支援卡与已识别训练伙伴，不包括 master `single_mode_unique_chara` 中的剧本 NPC。友情资格按普通类型支援卡、相同训练类型及羁绊至少 80 核对；团卡尚未解释，明确排除。评审加成取已完成的最新一期结果对应 `single_mode_11_check_point_eff` 的 `effect_type=202, effect_value_1=9`，没有评审历史时为零；不是按回合硬套固定成功奖励，也不是累计各期加成。

`evidence_point_gain` 从 master、人员、羁绊及评审结果生成预测，再对比服务端预览，不读取动作后的 Pt 净差作为输入。19,867 个去重预览全部匹配，覆盖人数 0–5、友情/非友情及加成 0/5/10/15。重复预览去重键保留实际预览值，因此同输入的反例不会被去重抹掉。加成 3、未观察卡组、岛训练、比赛、最终评审后规则不在这次验证范围。

结果位于 `artifacts/evidence/point-gain-audit-01/`。这批材料用于提出和检查解释，没有当作隔离的独立育成验收集；匹配不证明人员分布或友情出现概率。

### 评审提交与选择后结算

`CheckpointMasterData` 读取规划期、发展 Pt 溢出奖励和评审效果原始行；`CheckpointSettlement` 只处理已核验事件选择后的发展 Pt／体力分量。提交评审与选择后奖励分开建模，不能在提交端点立即回体。倍率原值、目标值、单期回体上限来自 master；换算和结算顺序由实包核对。属性、技能与后续事件不能混入该局部算子。核验方式见 [评审证据](checkpoint-evidence.md)。

### 训练生成与失败率

`TrainingFailureRate` 生成显示失败百分比；实际失败分布与后果是其他待实现规则。`TrainingFormulaCandidate` 根据基础值、支援效果、成长、干劲、人数与评审加成生成训练收益候选；使用精确有理数输出取整前值，不通过 epsilon 或经验整体缩放隐藏反例。三模式候选在当前可重建材料中数值匹配，但多个操作顺序符合观测，且未独立验收。详见 [三模式训练证据](training-modes-evidence.md)。

## 排除的实现

| 移交包实现或说明 | 不吸收的原因 |
| --- | --- |
| 彩圈概率 0.72、训练缩放 2.90/3.02、随机属性上限 ±1.5% | 未通过条件规律反推；改变模拟质量或游戏规则 |
| 平均事件回体、外出平均收益、非训练回合固定 +3.4 体力 | 把未知触发与效果合并为平均数，不能解释单次结算 |
| `ReplayYieldProvider` 读取已发生动作 delta | 把答案作为训练收益输入，不能证明未来生成能力 |
| `ReplayRunner` 每帧同步真人 before、评审前补齐实际 Pt | 会掩盖模拟累计误差，不能证明自主整局 |
| C++ Mecha 快照的随机支援事件、近似继承和粗略赛事奖励 | 参考 AI 的策略近似，不是完整 Pioneer 规则 |
| “零训练失败”或“v4/v6 各一次失败”的总结 | 相互矛盾；派生数据未保存明确训练结果，不能靠属性零差判定失败 |
| “训练不可用即比赛合法” | 从样本行为推断完整合法性，证据不足 |

移交包的 Python README 记录了其近似参数。当前训练采用本地实包拟合的分量公式，人员与Hint采用分层统计和参考实现相结合的模型。
