# 当前架构与契约

## 规则、策略与执行

`ISimulationScenario<TState,TDecision,TAction,TOutcome>` 的规则实现可以共享不可变数据，每条轨迹的可变信息归入 `TState`：

- `RulesIdentity` 标识实现和规则数据，资源来源与哈希单独记录。
- `CreateWorkspace` 创建轨迹独占工作区；`CopyState(in source, ref destination)` 复用目标容量，复制有效状态。已揭示事实随副本保留，不能重新抽取。
- `Inspect(in state, decisionOrdinal)` 返回下一决策、完整终局或明确停止。`DecisionId` 包含阶段、轨迹内递增序号和剧本身份键；Pioneer 的键包含回合和事件／命令编号。决策视图只在策略调用期间借用。
- `ValidateAction` 验证完整动作；不能只核验策略恰好枚举出的动作。建设计划必须保留顺序。
- `ApplyAction(ref state, in action, ref random)` 消费一次选择，结算到下一个实际决策点，可能仍处于同一回合。`ResumeAutomatic` 处理已消费动作的后续结算；未知步骤不能重复应用已提交效果。
- `GetOutcome` 只能读取完整终局。

策略只接收决策视图，不接收完整游戏状态。`ValidateCompletion` 检查策略的终局后置条件。`ActionScript` 按决策身份消费显式动作；缺项、错位和终局剩余步骤均返回 `ScriptMismatch`，不补选动作。

`PioneerScenario` 的自主路径从真实训练面板出发，推进建设、五期评审、合宿和固定 URA 决赛，结算终局指标。条件回放可单独执行耐力失败、岛训练、建设、Hint、Tucker、PJ、评审与末尾角色结局等分量。MCP 导入从抓包前缀恢复成功普通训练次数、已观察事件及评审历史。详见 [Pioneer 执行边界](pioneer-runtime.md)。

局部规则以纯输入输出函数组合：`PioneerPointGain` 接受人数、评审加成与已判定友情资格；`TrainingFailureRate` 接受 master 系数、体力、支援减免与状态偏移；`CheckpointSettlement` 接受明确事件身份和资源前态。它们不自行抽取人员或补选动作。`TrainingFormulaCandidate` 保留 BigInteger 审计参考实现；`TrainingNumericKernel` 提供精确数值结果，保持各原子量化及相乘顺序。适用语料零反例不等于完整内容覆盖或公式唯一性认证。

## 确定性与多线程

`SimulationRunner` 同步执行轨迹；每个 worker 独占可复用状态、策略游标和两条值类型随机流。规则随机流与策略随机流独立，种子只由根种子、样本编号、随机流域派生。PRNG 为固定实现的 `splitmix64-v1`，种子派生标识为 `sample-domain-mix-v1`，不使用 `System.Random`、时间或线程编号。

`RunBatch` 的样本数量由调用者显式指定，1..32 个 worker 领取连续的逻辑任务块。结果放回对应样本位置；评价器按输入顺序归约。调用者应按返回顺序评价，不按任务完成顺序累加。

同一起点、规则、种子、策略及计算设置下，各 worker 数的逐样本结果必须相同。增加批量样本数时，已有样本前缀不改变。`ForkInto` 精确复制状态、执行位置、两条 RNG 和策略游标；`ResetSample` 按新的逻辑样本身份派生未来随机流。规则和策略不得使用全局可变随机源，也不能以调用次序决定内容。

该一致性要求针对完成的固定样本批次。按现实时间取消可能留下不同数量的已完成轨迹；取消结果显式标为停止，不能冒充等质量的完整批量结果。

结果记录规则身份、根种子、随机算法和派生算法。确定性重算使用原始根状态、规则数据及脚本或策略配置。

未知机制、非法动作、脚本不匹配和取消产生 `TrajectoryResult.Status=Stopped`，携带结构化原因、执行位置、已消费动作数、已完整结算动作数及 RNG 末态。部分结算不算成功终局。其他程序错误继续抛出。批量取消后，每个请求槽位都有明确结果。

执行引擎要求 x64／AVX2。共享预编译数据与32个工作区的容量上限为8 GiB；原始包、调用者保留的分叉和批量结果不在此口径。Pioneer 按已支持片段的输入结构预分配容量，执行期不扩容，容量并非游戏人数或事件数量上限。详细契约见 [Core 执行器](core-engine.md)。

## 目标评价

`RootSearch.Evaluate` 将候选行动、轨迹执行和目标评价连接起来；候选之间复用工作区，按固定样本编号归约。后续策略、零达标及停止语义见 [回合推荐实现](recommendation.md)。

`TerminalMetrics` 是评价边界，属性和上限须已转换为经验证的游戏显示单位。它包含：

| JSON 字段 | 含义 |
| --- | --- |
| `attributes` | 终局五维属性 |
| `caps` | 终局有效五维上限 |
| `futureGainedSkillPoints` | 从模拟起点之后累计获得的技能 Pt，可为 `null` |
| `futureOverflow` | 从模拟起点之后真实被上限截断的五维累计值，可为 `null` |
| `verifiedAttributeRating` | 经验证的属性评价分，可为 `null` |

五维对象必须显式包含 `speed`、`stamina`、`power`、`guts`、`wisdom`。可空指标也须显式提供，未知时写 `null`。缺字段、重复字段、未知字段或错误类型均拒绝；目标需要的指标未知时拒绝评价。当前没有从实包净差自动推导累计溢出或累计技能 Pt。

条件按同一轨迹同时满足计算。例如 `GreaterThan 1201` 在整数属性中要求至少 1202。批量比较先比较同时达标率，再比较达标轨迹的平均五维评分或条件平均效用，口径由推荐入口决定。同一级 `terms` 加权求和。两个候选均没有达标轨迹时，先比较全部样本的平均条件总缺口，再按优先级比较全部样本均值。达标样本均值为 `null`。概率报告及统计边界见 [零达标建议与概率](recommendation.md#零达标建议与概率)。

`attribute` 指标累计边际曲线：控制点之间线性插值，每个已获得的整数属性点只计一次，最后一个控制点之后沿用该边际权重。降低高属性区间的边际权重不会降低已获得低属性部分的效用。使用 `decimal` 并尽量延后除法；任意非终止小数仍受 `decimal` 精度限制，溢出明确失败，不引入模糊相等阈值。

`deficit` 是有效上限减属性值；`overflow` 是路径中真实累计截断。负权重表示尽量减小该指标。这两个量不同，不能只从终局属性补算溢出。

`power-goal.json` 显式采用耐力、智力 >1201，先最小化速度不足和累计溢出之和，再提高力量。它是优先级示例，不是内置偏好；需要同级折中时将目标项放入同一级并修改权重。`stamina-curve-goal.json` 的边际权重在 801 以前为 10，之后线性下降，1201 起为 1。

评价器按每条轨迹先计算非线性效用，再求条件平均；不会先平均属性后套曲线，也不输出未经搜索得到的最佳动作。

`GoalEvaluator.Compile` 按显式属性范围预计算精确 `decimal` 曲线表；批量评价按固定样本顺序直接累计。范围外或所需指标未知时明确拒绝；停止轨迹不能伪造成终局指标。
